## 0.5.0 작은 마이크 입력 맞추기

**마이크 시작 → 마이크 음량 맞추기 · 3초 → 평소 크기로 말하거나 노래 → 녹음 시작** 순서로 사용하세요. 측정은 사용자가 버튼을 누른 경우에만 시작하고, 따로 WAV를 녹음하거나 서버로 보내지 않습니다. 녹음 중에는 측정과 입력 증폭 변경을 막습니다. 듣기는 별도로 체크해야 켜집니다.

이전에는 원래 작은 마이크 신호를 그대로 음정 검출기에 넣고 저장 단계에서만 크게 만들었습니다. 이제 **입력 증폭**으로 검출 전 레벨을 0~+36 dB 조절합니다. 듣기와 보정 파일에 모두 적용하고 `_original.wav`는 그대로 둡니다. 원본이 작다는 사실만으로 WAV 저장 단계의 손실을 의미하지는 않습니다. 기존 작은 원본을 다시 보정할 때에도 입력 증폭이 적용됩니다. 이미 큰 파일은 입력 증폭을 0으로 낮추세요.

맞춤 기능은 3초의 20 ms RMS 창 중 70백분위 값을 사용해 -22 dBFS로 맞출 입력 증폭을 계산하고, 측정한 피크가 -6 dBFS를 넘지 않게 증폭량을 제한합니다. +36 dB를 넘기지 않으며, 입력이 너무 작으면 적용하지 않습니다. **완료 시 입력 증폭을 설정하고 듣기와 녹음 크기를 각각 +6 dB로 바꾸며 잡음 차단을 끕니다.** 기존 +24 dB 저장 증폭을 그대로 더하지 않기 위한 설정입니다. 상용 LUFS 정규화나 지속적인 자동 게인 조절은 아닙니다. 프리셋을 바꿔도 맞춘 음량은 유지하며 앱을 닫으면 초기화됩니다.

측정할 때 실제 녹음할 목소리 크기로 말하세요. 조용히 있거나 큰 배경 소음만 들려주면 올바른 보컬 기준을 얻을 수 없습니다. 마이크/거리/Windows 설정이 바뀌면 다시 맞추세요. 이후 더 크게 말해 CLIP이 표시되면 입력 증폭을 낮추세요. 증폭이 과하면 입력을 제한하므로 음색이 거칠어질 수 있습니다. 입력 증폭 변경은 20 ms로 평활화하며 별도 오디오 지연 버퍼를 추가하지 않습니다. 잡음 차단을 켰다면 기준은 증폭된 입력에 적용됩니다.

사용자 제공 두 테이크의 전체 파일 RMS 비교에서 Windows 녹화의 한 채널은 약 -25.2 dBFS, PitchLab 원본은 -52.0 dBFS, 기존 보정음은 -34.2 dBFS였습니다. 두 테이크의 발성과 길이가 달라 이 수치로 Windows 자동 증폭이나 장치별 원인을 확정할 수는 없습니다. 새 입력 증폭은 작은 레벨을 보정하는 기능이며 입력 잡음을 제거하지 않습니다. 사용자 음성 및 파생 파일은 저장소와 배포 ZIP에서 제외합니다.

## 0.4.2 현재 기본 설정

작은 목소리가 안 들리거나 녹음이 작은 문제를 줄이기 위해 **잡음 차단 기본 끄기, HEADPHONES +12 dB, 녹음 크기 +24 dB**로 바꿨습니다. HEADPHONES의 0 dB는 음소거가 아니라 추가 증폭이 없다는 뜻입니다. 듣기를 켜야 출력되며, 저장 음량은 '녹음 크기'로 따로 조절합니다. 원본 WAV는 여전히 증폭하지 않습니다.

0.4.1의 고정 -60 dBFS 잡음 차단은 그보다 작은 목소리까지 무음으로 만들 수 있었습니다. 처음 실행할 때는 끄고 목소리가 잘 들리는지 확인한 뒤 필요하면 직접 켜세요. 이 변경으로 대기 잡음도 다시 들릴 수 있습니다. 잡음과 작은 목소리를 고정 레벨만으로 완전히 구분할 수는 없습니다.

기존 헤드폰 상한 0.03(약 -30.5 dBFS)은 정상적인 보컬도 작게 제한했습니다. 이를 **0.25(약 -12 dBFS)**로 조정했습니다. 기본 듣기 증폭은 +12 dB이며 250 ms 켜기 페이드, 20 ms 다이얼 평활화, 오류 시 차단과 즉시 음소거는 유지합니다. 이전보다 실제 출력이 커지므로 처음에는 Windows/헤드폰 자체 음량을 낮추고 시작하세요.

녹음 기본 +24 dB는 이전 +18 dB보다 제한기에 닿지 않는 구간에서 6 dB 큽니다. 이미 큰 목소리는 '녹음 크기'를 낮추세요. 최종 파일 상한은 -1 dBFS 샘플 피크로 유지합니다. 기존에 조용하게 저장된 파일은 '기존 WAV 음량 키우기'를 이용할 수 있지만, 이미 무음으로 잘린 목소리는 원본 WAV에서 다시 보정해야 합니다.

검증: 기존 잡음 기준보다 작은 음을 실제 콜백/워커에 넣어 통과하는지 확인했고, 보통 크기의 신호가 예전 헤드폰 상한에 눌리지 않는지 검사했습니다. 실제 WAV 쓰기에서 +24 dB, 원본 보존, 길이 유지도 확인했습니다. 실제 헤드폰이나 사용자 장치의 청취 음량은 측정하지 않았습니다. 아래 이전 버전 기록의 기본값은 현재 값과 다릅니다.

## 0.4.1 듣기를 켰을 때의 대기 잡음

**대기 잡음 줄이기**를 기본으로 켰습니다. 입력 레벨을 확인하고 작은 대기 잡음이 음정 보정과 공간 효과에 계속 들어가지 않도록 줄입니다. 기본 기준은 **-60 dBFS**이며, 잡음이 남으면 -54 쪽으로, 작은 목소리가 잘리면 -66 쪽으로 조절하세요. 표시되는 값은 증폭 전 입력의 기준입니다. 원본 WAV와 '기존 WAV 음량 키우기'는 이 처리를 거치지 않습니다. 보정 켜기를 꺼도 잡음 차단은 별도로 동작하며 체크를 끄면 부드럽게 해제됩니다.

3 ms 입력 에너지 추적, 1 ms 열기, 100 ms 유지, 60 ms 닫기와 서로 다른 열기/닫기 기준을 사용합니다. 버퍼 지연은 추가하지 않지만 작은 첫소리의 레벨과 끝음에는 영향을 줄 수 있습니다. 이 기능은 지속적인 잡음 제거 모델이나 60 Hz 전용 필터가 아닙니다. 말하는 중의 잡음, 실제 장치 끊김, 전기적 문제를 복구하지 않습니다.

디지털 무음은 두 엔진과 모든 스타일에서 잡음 차단을 꺼도 새 소리를 만들지 않았습니다(36개 조합). 합성 저레벨 험/잡음, 작은 목소리의 통과, 실제 콜백/워커의 최대 헤드폰 증폭 시 대기 출력도 검사합니다. 사용자 녹음의 마지막 0.25초를 반복한 로컬 비교에서는 +18 dB 저장 기준 기존 RMS 0.001856에서 새 결과가 24-bit 무음으로 내려갔습니다. 이 짧은 구간의 결과만으로 사용자 장치에서 들리는 모든 지직거림의 원인이 확정되거나 해결됐다고 판단하지는 않습니다. 개인 녹음과 파생 파일은 배포하지 않습니다.

잡음 차단 표시가 '대기 잡음 차단 중'이고 PHONES 미터도 0인데 계속 지직거리면 **진단 저장**으로 현재 버전의 기록을 확인해야 합니다. 진단에는 입력 피크·잡음 기준·게이트 상태도 포함합니다. 이전 버전의 오래된 진단으로 현재 장치 상태를 판단하지 마세요.

**NOWIMYOUNG / Bright**(빠른 보정·밝은 훅·짧은 메아리), **Royal 44 / Melodic**(긴 음의 흔들림·멜로디·룸)을 추가했습니다. 정확한 실제 세션 수치가 공개된 것으로 확인하지 못했으므로 자체 근사 프리셋입니다. 기존 6개와 함께 총 8개 스타일입니다.

## 0.4.0 작게 저장되는 녹음과 스타일 프리셋

**녹음 크기**를 추가했습니다. 기본 +18 dB이며, 작은 신호의 진폭을 약 7.94배 키워 보정 WAV에 저장합니다. 여전히 작으면 +24 dB를 시도하세요. 원본 녹음과 헤드폰 음량은 별개이며, 녹음 시작 시 정한 값은 해당 녹음이 끝날 때까지 고정합니다. 이미 큰 입력은 0 dB로 낮추세요. 증폭은 잡음도 키우며 최종 제한기에 계속 닿으면 질감이 거칠어질 수 있습니다.

이미 녹음한 파일은 마이크를 멈춘 뒤 **기존 WAV 음량 키우기**를 누르세요. 현재 녹음 크기만 적용한 `_louder.wav`를 새로 만듭니다. 음정 보정이나 스타일 효과를 다시 적용하지 않으며 입력 파일을 덮어쓰지 않습니다. 모노/스테레오 입력을 받아 24-bit 모노로 저장하고, 샘플 수를 유지합니다. 최종 상한은 -1 dBFS 샘플 피크이며 LUFS/트루피크 정규화는 아닙니다.

T-Pain / Snap, Travis Scott / Space, Future / Room, Sik-K / Air Hook, CHANGMO / Upfront, ASH ISLAND / Emo를 추가했습니다. 음정 보정 속도와 강도뿐 아니라 음색, 압축, 포화, 박자 딜레이, 룸도 달라집니다. **공식 세션 설정이 아닌 스타일 참고용 자체 프리셋**입니다. 국내 세 명의 정확한 공개 수치는 확인하지 못했습니다. 설정값·조사 출처·확인하지 못한 부분은 [프리셋 가이드](../PRESET-GUIDE.txt)에 정리했습니다.

프리셋 선택 후 곡의 **KEY / SCALE / SONG BPM**을 맞추세요. STYLE FX를 줄이면 공간과 음색 효과가 줄고, 0%에서는 음정 보정만 남습니다. 프리셋을 바꿔도 곡의 음 선택·BPM·헤드폰·녹음 크기는 유지합니다. BPM은 마이크를 멈춘 상태에서 변경합니다. 끝부분 잔향을 녹음하려면 노래를 마친 뒤 1~2초 기다렸다 녹음을 끝내세요. 파일 보정은 길이를 유지하므로 파일 끝 이후 잔향을 추가하지 않습니다.

실제 WAV 재읽기에서 +18 dB 증폭, 원본 보존, 길이 유지, 무음과 과대 입력 상한을 확인했습니다. 여섯 스타일은 44.1/48/96 kHz 합성음 및 공개 발화로 검사했습니다. 실제 장치를 재생하거나 아티스트와의 청취 유사도를 검사하지는 않았습니다.

## 0.3.2 듣기를 켜도 너무 작게 들리는 문제

기존 헤드폰 기본값 -36 dB는 보정음을 약 1/63배로 줄이고, 최대로 올려도 -18 dB였습니다. Windows 입력 오류를 고친 뒤에는 정상적인 작은 목소리가 거의 들리지 않을 수 있었습니다. **기본값을 0 dB, 조절 범위를 -60~+24 dB로 바꿨습니다.** 0 dB는 보정된 신호를 추가로 감쇠하지 않습니다. 작으면 오른쪽 HEADPHONES를 +6, +12 dB 순서로 올릴 수 있습니다. 이 다이얼은 녹음 파일의 음량을 바꾸지 않습니다.

듣기는 여전히 직접 체크해야 켜집니다. 출력 상한 0.03, 250 ms 켜기 페이드, 오류 음소거를 유지하며 다이얼 변경에도 20 ms 평활화를 적용했습니다. 하단 **PHONES 미터는 보호 처리가 끝난 실제 출력 버퍼**를 표시합니다. 체크할 때 하단에 선택된 출력 장치 이름이 나옵니다. 미터는 움직이는데 안 들리면 **마이크 멈추기 → 오디오 설정**에서 출력 장치가 실제 연결한 헤드폰인지 확인하세요. 장치 밖의 Windows 음량이나 헤드폰 음압은 이 미터로 측정하지 않습니다.

작은 마이크 신호를 넣은 콜백/워커 검사에서 기본 출력과 +12 dB 증가, 끌 때 즉시 무음, 실제 출력 미터 일치를 확인했습니다. 44.1/48/96 kHz에서 최대 증폭의 출력 제한과 다이얼 전환도 검사했습니다. 실제 장치에서 소리를 재생하지는 않았습니다.

## 0.3.1 지직거림 수정

일부 Windows 마이크가 반환하는 일반 `WAVE_FORMAT_IEEE_FLOAT`(tag 3)를 JUCE 8.0.15의 WASAPI 코드가 정수 PCM으로 잘못 판정하는 오류를 수정했습니다. 기존 코드는 확장 형식(tag 65534)의 float만 인식했습니다. 작은 목소리의 float 비트가 큰 정수 신호로 해석되어, **보정 전 원본부터 큰 잡음이 생기고 보정음도 기계음처럼 변할 수 있었습니다.** 캡처와 재생의 형식 선택에 모두 수정이 적용됩니다. PCM과 확장 float의 처리는 유지합니다.

`cmake/PatchJuceWasapi.cmake`가 고정된 JUCE 소스에 패치를 적용합니다. Git 다운로드와 배포 ZIP의 의존 소스 모두 같은 수정을 받으며, 예상과 다른 코드에는 빌드를 중단합니다. `Tests/WasapiFormatTests.h`에서 실제 JUCE 바이트 변환기로 기존 큰 파형 점프를 재현하고 수정 후 입력 오차가 0인지 검사합니다.

**이전 앱을 종료하고 최신 실행 파일로 교체하세요.** 저지연 보정 엔진, 버퍼 설정, 출력 제한 상한은 변경하지 않았습니다. 앱 내부 지연도 48 kHz/128샘플 메모리 검사에서 약 29.33 ms입니다. 물리 장치로 노래하거나 헤드폰으로 듣는 검사는 하지 않았으므로 장치별 실제 지연과 청취 품질에는 별도 확인이 필요합니다. 이전의 모든 잡음 원인이 이번 오류였다고 단정하지 않습니다.

개인 녹음과 복원 파일은 저장소 및 배포 ZIP에 포함하지 않습니다.

## 0.3 실시간 지연 개선

마이크와 실시간 녹음은 **Signalsmith의 22 ms 처리 창**, WAV 파일 보정은 기존 Rubber Band 엔진을 사용합니다. 두 경로는 질감과 보정 정밀도가 다를 수 있습니다. 파일 보정의 길이 맞춤은 유지합니다.

48 kHz에서 입력 펄스부터 헤드폰 출력 버퍼까지 실제 샘플 위치를 비교한 결과입니다. 오디오 장치를 열지 않는 메모리 검사이므로 **장치/드라이버 지연은 별도로 더해집니다**.

| 실제 장치 버퍼 | 앱 내부 측정 지연 |
|---|---:|
| 64 또는 128 samples | 29.33 ms |
| 256 samples | 34.67 ms |
| 512 samples | 45.33 ms |

기존 48 kHz/512 기준 약 107 ms에서 줄였습니다. 현재 기본 요청은 48 kHz/128 samples입니다. Windows Audio (Low Latency Mode)를 우선 선택하고 처음 열기에 실패하면 일반 Windows Audio로 시도합니다. 장치가 요청한 버퍼를 지원하지 않으면 실제 버퍼가 커질 수 있습니다. 오디오 설정에서 128 samples가 제공되는지 확인하세요. 끊기면 256으로 높일 수 있습니다. 화면에는 실제 버퍼와 장치 보고 지연까지 더한 DELAY를 표시합니다. 시작 때 작업 스레드가 늦게 깨어 추가 대기한 경우도 이 값에 반영합니다.

처리 스레드의 작업 단위는 512→128 samples, 최소 대기 버퍼는 2048→256 samples로 줄였습니다. 실시간 경로의 두 제한기는 각각 5→1 ms로 줄였으며 기존 출력 상한과 오류 차단을 유지합니다. 대기 시간이 줄어든 만큼 컴퓨터 부하에 대한 여유는 작아집니다.

짧은 창은 음정 정밀도·음색 보존과 절충합니다. 44.1/48/96 kHz, 음색 보존 켬/끔, 67–987 Hz의 9개 합성 음에서 25 cents 이내 기준을 검사했으며 결과는 TEST-RESULTS.txt에 있습니다. 파일 엔진의 기존 정확도 기준은 그대로입니다. 저지연 엔진으로 공개 발화 파일도 재처리해 출력 상한과 파일 정렬을 검사했습니다. 실제 노래의 청취 품질은 확인하지 않았습니다.

첫 음정 검출에는 별도의 관측 시간이 필요합니다(48 kHz에서 약 32 ms부터 첫 판정). Retune/Humanize는 이후 음정 변화 속도를 조절합니다. 이 반응 시간과 오디오가 통과하는 지연은 다릅니다.

## 사용하기

ZIP을 풀고 `PitchLab.exe`를 실행하세요. 시작할 때 오디오 장치를 자동으로 열거나 소리를 재생하지 않습니다.

**기존 목소리 파일:** 프리셋과 키·스케일을 선택하고 **WAV 파일 보정**을 누릅니다. 녹음 폴더에 `_tuned.wav`, `_original.wav`, `_report.txt`가 생깁니다. 자동 재생하지 않습니다. 처리 시작 시 설정을 사용하며, 처리 도중 변경은 다음 파일에 적용됩니다. 16–96 kHz, 모노/스테레오, 최대 1시간 WAV를 지원합니다. 스테레오는 모노로 평균합니다. 파일 처리 시 지연을 제거하므로 원본과 결과 길이가 같습니다. 음량을 자동 정규화하지 않습니다.

**마이크:** **오디오 설정 → 마이크 시작 → 녹음 시작** 순서입니다. 보정음과 원본을 별도 24-bit 모노 WAV로 저장합니다. **헤드폰으로 듣기**를 켜야 출력됩니다. 듣기를 꺼도 녹음됩니다. Windows와 헤드폰 자체 음량을 낮게 두고 시작하세요. 기존 0.1.0은 사용하지 마세요.

**강하게 음에 붙는 효과:** `Hard tune`을 선택하고 노래의 키·스케일을 맞추세요. 건반으로 보정에 사용할 음을 직접 고를 수 있습니다. 건반은 소리를 내는 악기가 아닌 음 선택기입니다. 모든 음을 끌 수는 없습니다.

## 처리 변경과 진단

짧은 자음·무성음 구간에서는 기존 보정 비율을 유지하고 긴 무음에서는 부드럽게 복귀합니다. 긴 음의 Humanize, 음역 선택, 직접 고른 음으로 보정하는 기능을 추가했습니다. 직접 고른 음으로 최대 한 옥타브 이내에서 이동하며, 큰 이동은 음색 변화가 생길 수 있습니다.

무거운 피치 처리는 별도 스레드에서 수행합니다. **진단 저장**은 장치 이름, 처리 시간, 시간 초과 블록, 입력/출력 버퍼 이상, XRUN을 녹음 폴더에 기록합니다. 음성 내용은 포함하지 않습니다. 오류로 멈추면 자동 저장합니다. 시작 0.5초 이후 드라이버 XRUN 증가도 화면 타이머에서 감지해 출력을 끄고 녹음을 중단합니다. 드라이버가 보고하지 않는 끊김은 이 수치로 검출할 수 없습니다.

오류: 1 입력 버퍼 넘침, 2 출력 데이터 부족, 3 비정상 신호, 4 DSP 스레드 시작 실패, 5 드라이버가 보고한 끊김. 오류 이후 듣기를 자동 재개하지 않습니다.

## 출력 보호와 한계

헤드폰 기본 게인은 +12 dB, 범위는 -60~+24 dB이며 켤 때 250 ms에 걸쳐 올라갑니다. 다이얼 변경은 20 ms로 평활화합니다. 보정 엔진은 고정 -6 dB 게인과 최대 0.5의 미리보기 제한기를 거칩니다. 저장 경로는 그 뒤에 녹음 크기를 적용하고 최대 약 0.89125(-1 dBFS 샘플 피크)로 제한합니다. 파일 증폭은 추가 지연을 만들지 않습니다. 마이크 경로는 각 1 ms, 파일 경로의 출력 제한기는 5 ms 미리보기를 사용합니다. 헤드폰 경로는 최대 0.25(약 -12 dBFS)까지 별도로 제한합니다. 디지털 제한은 실제 헤드폰 음압을 보장하지 않습니다.

48 kHz / 128 samples 기준 앱 지연은 약 **29.3 ms + 장치 지연**입니다. DELAY는 계산값과 드라이버 보고치이며 물리적 왕복 측정값이 아닙니다. 상용 플러그인 수준의 낮은 지연을 달성했다고 주장하지 않습니다.

한 사람의 분리된 보컬용입니다. 반주, 숨소리, 거친 발성, 여러 사람 입력은 검출 오류가 생길 수 있습니다. 0.3.1에서 확인한 Windows 입력 형식 판정 오류는 수정했습니다. 합성 신호와 공개된 실제 **발화** 파일로 처리 동작을 검사했으며, 실제 노래의 자연스러움·마이크/헤드폰의 모든 끊김 해소·상용 Auto-Tune과 동등한 품질은 검증하지 않았습니다.

가상 마이크, VST, ASIO는 포함하지 않습니다. 윈도우 녹화·디스코드의 마이크를 자동 교체하지 않습니다. 앱 자체 WAV 녹음 기능을 사용하세요. 상용 제품의 코드·브랜드·화면 자산은 사용하지 않았습니다.

## 빌드와 검사

Visual Studio 2022 C++ 데스크톱 개발 도구, Windows SDK, CMake 3.24 이상이 필요합니다. `build.ps1`은 포함된 의존 소스 아카이브 또는 고정된 Git 커밋을 사용해 빌드하고 내장 검사를 실행합니다.

마이크용 엔진으로 파일을 검사하려면 `--render-live 입력.wav 출력폴더 프리셋번호 [녹음dB] [BPM] [입력dB]`을 사용합니다. 일반 파일 보정은 `--render`로 같은 인수를 받습니다. CLI에서 생략한 녹음 dB와 입력 dB는 기존 호환을 위해 0, BPM은 140입니다. 0.4.2의 CLI 보정은 잡음 차단을 기본으로 끕니다. 프리셋 번호는 0 Natural / 1 Tight / 2 Hard / 3 T-Pain / 4 Travis Scott / 5 Future / 6 Sik-K / 7 CHANGMO / 8 ASH ISLAND / 9 NOWIMYOUNG / 10 Royal 44입니다.

증폭만 하려면 `--boost-wav 입력.wav 출력폴더 [녹음dB]`를 사용하며 기본 +18 dB입니다. `--self-test 출력폴더`, `--render-ui 출력.png`도 지원합니다. 경로에 공백이 있으면 따옴표로 감싸세요. CLI는 오디오 장치나 재생을 사용하지 않습니다. UI 렌더는 창 없이 컴포넌트를 이미지로 그립니다.

`STYLE-TEST-RESULTS.txt`에는 현재 8개 스타일 발화 처리 및 파일 증폭 검사를 기록했습니다. `Tests/verify_styles.py 실행파일 입력.wav 결과폴더`로 재현할 수 있습니다(Python, numpy, soundfile 필요). 출력은 원본과 길이가 같고 모노 원본의 샘플을 보존하는지 확인하며, 아티스트 유사도나 청취 품질 점수는 아닙니다.

`TEST-RESULTS.txt`는 내장 검사, `VOICE-TEST-RESULTS.txt`는 파일 엔진의 외부 WAV 재읽기 검사 기록이며, `LIVE-VOICE-TEST-RESULTS.txt`는 이번 마이크 엔진의 동일 검사를 기록합니다. 합성음의 기본 음정 외에 직접 음 선택, 비브라토 보정 반응, 출력 제한, 버퍼 이상, 비정상 수치, 프리셋과 건반의 DSP 전달을 검사합니다. WAV 검사는 실제 발화 약 45.5초를 Natural/Hard로 각각 처리한 6회와 짧은 스테레오·무음 각 2회입니다. 길이·원본 정렬·무음·출력 상한·프리셋 차이를 확인했고 소리는 재생하지 않았습니다.

외부 검증: `python Tests/verify_render.py INPUT OUTPUT`. Python 표준 라이브러리만 사용합니다. 입력은 24-bit PCM WAV, 결과 폴더는 `OUTPUT/preset-0/입력이름/` 및 `OUTPUT/preset-2/입력이름/` 구조입니다.

발화 출처: [librosa 예제](https://librosa.org/doc/dev/recordings.html), [LibriSpeech SLR12](https://www.openslr.org/12/), CC BY 4.0. Garth Comira(5703-47212-0000), Heather Barnett(198-209-0000), Anders Lankford(3436-172162-0000). 테스트에서는 librosa/data의 22050 Hz OGG를 48000 Hz PCM으로 변환했습니다. 발화 파일과 그 처리 결과는 배포하지 않습니다. `Examples`는 프로젝트에서 생성한 합성 테스트 음입니다.
