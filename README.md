# PitchLab 0.1.1 — 실시간 보컬 보정 공부용 앱

Windows 10/11 x64용 독립 실행 앱입니다. 마이크 소리를 음계에 맞춰 보정하고, 그 소리를 들으면서 WAV 파일로 녹음할 수 있습니다. 음악 작업 프로그램이나 계정은 필요 없습니다. 오디오를 서버로 보내지 않습니다.

**[Windows 실행 파일과 전체 소스 ZIP 다운로드](https://github.com/YSL-RyuDo/pitchlab/releases/latest)** — 릴리스의 `PitchLab-Windows.zip`을 풀고 실행하세요. Git 저장소에는 프로젝트 소스와 합성 테스트 음이 들어 있으며 실행 파일과 의존 라이브러리 소스 아카이브는 릴리스 ZIP에 포함됩니다.

## 0.1.1 출력 보호 수정

0.1.0에서 헤드폰으로 지직거림과 반복 끊김이 보고되어 사용을 중단하고 이 버전으로 교체하도록 안내합니다. 보고된 현상의 정확한 원인은 실제 장치에서 재현하지 못했습니다. 이번 수정은 처리 지연에 대한 대응과 출력 제한을 보강합니다.

- 피치 검출과 피치 이동을 별도 DSP 스레드로 이동했습니다. 장치 콜백은 고정 크기 버퍼 복사와 헤드폰 출력 보호만 수행합니다.
- 약 43 ms의 처리 여유 버퍼를 추가했습니다(48 kHz, 장치 버퍼 512 기준). 버퍼가 모자라거나 넘치면 즉시 무음으로 전환하고 녹음을 중단합니다. 자동으로 소리를 다시 켜지 않습니다.
- 헤드폰 듣기는 시작할 때마다 꺼집니다. 기본 음량은 -36 dB, 조절 범위는 -60~-18 dB이며, 켤 때 250 ms에 걸쳐 올라갑니다. 녹음 음량과 별개입니다.
- 보정음에는 5 ms 미리보기 제한기(최대 0.5, 약 -6 dBFS), 헤드폰에는 별도 제한기(최대 0.03, 약 -30.5 dBFS)를 적용합니다. 디지털 제한은 헤드폰의 실제 음압을 보장하지 않습니다.
- 비정상 입력, 버퍼 이상은 출력을 차단합니다. 오류 번호: 1 입력 버퍼 넘침, 2 출력 데이터 부족, 3 비정상 신호, 4 처리 스레드 시작 실패.

검증은 소리를 재생하지 않는 합성 신호 검사로 진행했습니다. 실제 마이크·헤드폰·드라이버 조합의 끊김 해소는 아직 확인하지 못했습니다. 기존 문제를 확인하려고 큰 음량으로 다시 재생하지 마세요.

## 바로 사용하기

1. `PitchLab.exe`를 실행합니다.
2. 유선 헤드폰을 연결하고 **마이크 / 헤드폰 설정**에서 입력과 출력을 선택합니다. 처음에는 기본 장치를 사용합니다.
3. **마이크 시작**을 누릅니다. 말하거나 노래하면 입력 음과 목표 음, 입력 레벨이 표시됩니다.
4. **헤드폰으로 듣기**를 켜면 보정된 목소리가 들립니다. 시작할 때마다 꺼져 있으며, Windows와 헤드폰 자체 음량도 낮춰 두세요.
5. **녹음 시작 → 녹음 끝내기**를 누릅니다. 보정음과 원본이 각각 저장됩니다. 듣기를 꺼도 녹음은 됩니다.
6. **녹음 폴더 열기**로 결과를 확인합니다. 기본 위치는 실행 파일 옆 `Recordings` 폴더이며, **저장 위치 변경**으로 바꿀 수 있습니다.

처음에는 `Chromatic / 12 ms / 100%`로 시작해 보세요. 키를 모를 때 Chromatic은 모든 반음 중 가까운 음에 맞춥니다. 곡의 정답 멜로디를 알아내는 기능은 아닙니다.

| 조절 | 동작 |
|---|---|
| 키 · 스케일 | Chromatic, 장조, 자연단음계, 마이너 펜타토닉 지원 |
| 보정 속도 | 0–15 ms는 빠르게 음에 붙는 효과, 50–100 ms는 느린 변화. 이 값은 전체 오디오 지연과 다릅니다. |
| 보정 강도 | 100%는 목표 음까지, 0%는 피치 이동 없음 |
| 목소리 음색 유지 | 피치를 바꿀 때 포먼트 보존을 켜거나 끕니다. |
| 보정 켜기 | 끄면 지연을 맞춘 원래 소리로 부드럽게 전환합니다. |
| 헤드폰 음량 | 듣기 음량만 조절합니다. 저장되는 파일의 음량에는 영향을 주지 않습니다. |

## 저장되는 파일

- `take_날짜_시간_번호_tuned.wav`: 보정 설정과 고정 -6 dB 게인, 출력 제한기를 적용한 소리
- `take_날짜_시간_번호_original.wav`: 보정 전 원본. 비교하기 쉽도록 보정 경로의 기준 지연을 맞췄습니다.
- 둘 다 24-bit PCM, 모노이며 오디오 장치의 실제 샘플레이트를 사용합니다.
- 앱을 정상 종료하거나 마이크를 멈추면 진행 중인 녹음도 마무리합니다.
- 한 번에 최대 1시간을 녹음하고 자동 저장합니다. 디스크 기록 실패나 녹음 버퍼 넘침은 화면에 오류로 알립니다.

`Examples`에는 사람의 목소리가 아닌 **합성 테스트 음** 원본과 보정음이 들어 있습니다. 213 → 약 207.65 Hz, 432 → 440 Hz, 452 → 440 Hz 순서입니다.

## 현재 버전의 범위

- **학습용 첫 버전**입니다. 상용 Auto-Tune과 동일한 알고리즘이나 음질을 재현한 것은 아닙니다.
- 48 kHz에서 엔진·처리 여유 버퍼·헤드폰 제한기의 합산 기준 지연은 약 **107 ms**입니다(장치 버퍼 512 기준). 장치 버퍼가 크면 더 늘어납니다. 여기에 오디오 장치의 입출력 지연이 더해집니다. 실제 노래할 때 지연을 느낄 수 있습니다. 화면의 예상 왕복 값은 드라이버 보고치 기반이며 물리적인 왕복 측정값은 아닙니다.
- 한 사람의 분리된 보컬, 대략 65–1000 Hz의 기본 음을 대상으로 합니다. 반주와 목소리가 같은 마이크로 크게 섞이거나, 숨소리·거친 발성·여러 사람이 동시에 입력되면 음을 잘못 잡을 수 있습니다.
- 초반 음절과 급격한 음정 변화에서는 검출 안정화 시간이 필요합니다. 큰 보정이나 일부 발성에서는 질감 변화가 생길 수 있습니다.
- 이 앱의 녹음 기능에 보정음이 저장됩니다. 윈도우 녹화·디스코드 등의 **마이크 입력을 자동 교체하지는 않습니다**. 가상 오디오 장치와 별도 연결은 포함하지 않았습니다.
- 마이크의 입력 채널은 하나만 사용합니다. 장치 설정에서 원하는 채널을 선택하세요. 실행 중에는 장치 설정을 잠그며, 장치 연결이 끊기면 녹음을 마무리하고 재시작 안내를 표시합니다.
- 앱 설정은 재실행하면 초기값으로 돌아갑니다. ASIO 및 VST 플러그인 출력은 이 버전에 포함하지 않았습니다.

## 공부할 순서

1. `Source/PitchEngine.h`의 `PitchDetector`: YIN 차이 함수, 정규화, 유성음 판별, 포물선 보간으로 Hz를 구합니다.
2. 같은 파일의 `midiFromHz`, `nearestNote`: Hz를 MIDI 음높이로 바꾸고 키·스케일에서 가까운 음을 고릅니다. 경계에서 음이 자꾸 바뀌지 않도록 12-cent 히스테리시스를 사용합니다.
3. `PitchEngine::process`: 보정 속도를 평활화한 뒤 Rubber Band에 피치 비율을 전달합니다. 고정 길이 블록 변환, 지연을 맞춘 원본, 전환과 음량 평활화도 여기 있습니다.
4. `Source/AudioEngine.h`: JUCE의 오디오 콜백으로 마이크를 받고 헤드폰에 보냅니다. 별도 DSP 스레드와 두 FIFO가 무거운 처리를 담당하며, 버퍼 이상은 자동 차단합니다. `Source/OutputGuard.h`에는 미리보기 제한기와 듣기 보호가 있습니다.
5. `Source/Recorder.h`: DSP 스레드는 고정 크기 FIFO에 복사만 하고, 별도 스레드가 두 WAV 파일을 기록합니다.
6. `Source/Main.cpp`: 한국어 UI, 장치 선택, 상태 표시, 파일 위치와 녹음 수명 관리입니다.
7. `Tests/DspTests.cpp`: 마이크 없이 합성음을 넣고 **실제 출력 주파수**를 검사하는 테스트입니다.

피치 검출·음계 선택·자동 보정 제어는 프로젝트 코드입니다. 파형을 실제로 피치 이동하는 부분은 **Rubber Band 4.0.0**, 오디오 장치와 UI는 **JUCE 8.0.15**를 사용했습니다. 릴리스 ZIP의 `ThirdParty`에 의존 라이브러리의 전체 소스 아카이브도 함께 제공합니다.

## 빌드와 자동 검사

필요 도구: Visual Studio 2022의 C++ 데스크톱 개발 도구, Windows SDK, CMake 3.24 이상. 현재 PC의 설치된 도구로 Release x64 빌드했습니다.

PowerShell에서 이 폴더의 `build.ps1`을 실행하면 포함된 의존 소스 아카이브를 임시 빌드 폴더에 풀고 컴파일합니다. Git으로 받은 저장소처럼 아카이브가 없는 경우에는 CMake가 고정된 커밋의 의존 소스를 내려받습니다. 이때는 Git과 첫 빌드 시 인터넷 연결이 필요합니다. 보안 설정이나 실행 정책을 변경하는 스크립트는 포함하지 않았습니다.

```powershell
.\build.ps1
```

빌드 폴더를 지정할 수도 있습니다.

```powershell
.\build.ps1 -BuildDirectory C:\dev\PitchLab-build
```

완성된 앱은 이 폴더의 `PitchLab.exe`에 복사됩니다. 기존 앱은 먼저 닫아 주세요. `--self-test`는 마이크를 열지 않고 DSP와 WAV 통합 검사를 수행합니다. 지정한 폴더에 테스트 WAV와 검사 로그가 생성됩니다.

```powershell
$p = Start-Process .\PitchLab.exe -ArgumentList '--self-test "C:\dev\PitchLab-check"' -Wait -PassThru
$p.ExitCode
```

`TEST-RESULTS.txt`에 이 빌드에서 통과한 검사 결과를 기록했습니다. 자동 검사 대상은 합성음 보정, 음계 선택, 무음·잡음, 보정 끄기, WAV 재읽기와 반복 녹음, 제한기 과입력·펄스, 듣기 켜기/끄기, 실제 콜백과 DSP 스레드의 가변 블록 처리·FIFO 순환·버퍼 부족/넘침·NaN 차단입니다. 콜백 검사도 메모리 버퍼만 사용하며 오디오 장치를 열지 않습니다. 실제 장치의 소리와 지연은 검증하지 않았습니다.

제공한 0.1.1 실행 파일은 Release x64 빌드 후 내장 자동 검사를 통과했습니다. 이전 작업에서 이 PC의 앱 제어 정책이 일부 별도 빌드의 실행을 차단한 적이 있습니다. `build.ps1`은 컴파일 성공과 실행 검사 실패를 구분해 알리며 보안 설정을 변경하지 않습니다.
